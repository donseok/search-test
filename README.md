# MES 검색 실험실

냉연 공장 MES 재구축을 위한 로컬 검색 PoC. Python 3.9 이상만 있으면 됩니다. 합성 샘플 14건을 사용하며 실제 공장 데이터는 없습니다.

## 실행

```sh
python3 app.py
```

http://127.0.0.1:8000 접속. 포트 변경: `PORT=8001 python3 app.py`.
첫 실행 시 `data/mes.sqlite3`를 자동 생성하며 DB 파일은 Git에서 제외합니다. 회사 PC에서 clone 후 같은 명령으로 실행하면 샘플 DB가 다시 만들어집니다. 외부 패키지나 인터넷 연결은 필요하지 않습니다(웹폰트는 연결 실패 시 시스템 폰트 사용).

```sh
python3 -m unittest discover -s tests -v
```

## 검색 설계

> 동작 원리와 도식: [docs/HOW_SEARCH_WORKS.md](docs/HOW_SEARCH_WORKS.md)

1. Unicode NFKC + casefold + 공백·구분자(`_`, `-`, 각종 대시) 제거: 모든 검색어와 문서 필드에 적용. `프 로 젝 트`, `PROJECT`, `RAL_9006`, `ral-9006`, `rAl 9006`, `cold-rolling`, 분해형 한글, 전각 영문 처리. `.`과 `/`는 의미가 있으므로 유지(`1.2` ≠ `12`).
2. 문서별 동의어/별칭: `프로젝트 ↔ project`, `코일 ↔ coil`. 자동 번역이 아니므로 업무 용어를 계속 등록해야 합니다.
3. 제목/별칭 부분 검색: `프로젝` → `프로젝트`. 본문도 정규화 후 부분 검색.
4. Levenshtein 거리: 3~5자는 1회, 6~30자는 2회까지 편집 허용. 길이 대비 거리 34% 이하만 허용. `후로젝트` → `프로젝트`. 짧은 검색어와 숫자 포함 값(`RAL9007` ≠ `RAL9006`), SPCC/SPCD 강종 별칭은 오타 보정 제외.
5. 정확/정규화 100점 > 부분 85점 > 본문 75점 > 오타 62/54점. 점수는 상대적인 규칙 기반 순위이며 확률이 아닙니다. 동률은 문서 ID순.

공백·구분자 제거는 다른 단어를 합칠 수 있고(`A-1 2` = `A-12`), 일반 오타 보정도 의미가 다른 용어를 포함할 수 있습니다. 모든 오타·음역을 보장하지 않습니다. UI에서 오타 허용을 끄고 비교할 수 있습니다. `SPCE`가 `SPCC`로 잘못 검색되지 않는 회귀 테스트를 포함합니다. 운영 시에는 강종, 주문번호, 코일번호를 별도 코드 필드로 분리해 정확/접두 검색 정책을 적용해야 합니다.

## 데이터 변경과 API

`app.py`의 SEED는 초기 샘플입니다. 기존 행은 INSERT OR IGNORE로 보존됩니다. 샘플 변경을 다시 반영하려면 서버를 종료하고 로컬 DB를 삭제 후 재실행하세요(기존 로컬 데이터가 사라집니다). 직접 SQLite로 documents 테이블을 수정할 수도 있습니다. aliases는 JSON 문자열 배열입니다. 검색 시 항상 DB를 읽습니다.

`GET /api/search?q=후로젝트&category=공통&fuzzy=1`

응답: query, normalized, total, elapsed_ms, results. 각 결과에는 score, reason, matched가 포함됩니다. 빈 검색어는 전체 조회, 100자 초과는 HTTP 400. 범위 값은 SQL 파라미터로 전달하고 결과를 DOM textContent로 표시합니다. DB 파일을 제공하는 HTTP 경로는 없습니다.

## 운영 MES로 확장

이 구현은 전체 문서를 읽고 별칭과 비교하는 기능 검증용입니다. 대용량 응답시간 검증이나 운영 검색엔진을 대체하지 않습니다. 조회 시간은 서버 검색 시간만 포함합니다. 여러 단어 AND/OR, 초성, 키보드 한영 오입력, 형태소 분석, 권한 필터는 아직 구현하지 않았습니다.

- 정규화된 검색 컬럼과 업무 동의어 사전을 별도로 유지하고 변경 시 검색 인덱스도 갱신합니다.
- PostgreSQL 도입 시 pg_trgm GIN/GiST 인덱스로 부분/유사 검색 후보를 줄이고, 위 순위 규칙으로 재정렬합니다. 짧은 문자열은 별도 정책이 필요합니다.
- SQLite FTS5 trigram도 부분 검색 후보 추출에 쓸 수 있으나 3자 미만 검색과 오타 보정은 별도 처리해야 합니다. 이번 PoC에서는 FTS5를 사용하지 않습니다.
- 공장 실제 용어·검색 로그로 정답셋을 만들고 Recall@K, Precision@K, 무결과율, 오검색률, p95 지연을 측정한 뒤 임계값을 조절합니다.
- 운영 연결 전 사용자별 문서 접근 권한을 검색 후보 단계에 적용합니다. 현재 서버는 127.0.0.1에만 바인딩하며 인증 기능이 없습니다.

근거: [SQLite FTS5](https://www.sqlite.org/fts5.html), [PostgreSQL pg_trgm](https://www.postgresql.org/docs/current/pgtrgm.html).
